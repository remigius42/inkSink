## Why

inkSink is named after the graph-theory concept of a terminal node where
information flows to rest — but today it only pulls data from external services.
The Display Server makes the name literal: any device on the LAN can push
content directly to the screen, enabling home automation dashboards, calendar
pushes, and custom scripts without building a dedicated App for each source.

## What Changes

- New `display_server` App (`src/inksink/display_server/`) that runs as a
  background thread alongside the main process when enabled
- `POST /render` endpoint accepting `image/png` or `text/html` body with
  optional `?mode=1bit|4gray` query parameter; feeds content directly to the
  Compositor
- HTTP listener: open, LAN trust, no authentication
- HTTPS listener: self-signed cert generated by Ansible; optional bearer token
  via `apps.display_server.token`
- New Ansible role (`display_server`) that generates the self-signed cert on
  first deploy and configures the service
- New config keys: `apps.display_server.enabled` (default `false`),
  `apps.display_server.http_port`, `apps.display_server.https_port`,
  `apps.display_server.token` (optional)

## Capabilities

### New Capabilities

- `display-server`: HTTP+HTTPS endpoint that accepts pushed PNG or HTML and
  renders it to the e-ink display via the Compositor

### Modified Capabilities

- `ansible-provisioning`: new `display_server` role for cert generation and
  service configuration
- `config`: new `apps.display_server.*` keys
- `ui-compositor`: `set_content()` gains an optional `mode` parameter

## Impact

- `src/inksink/display_server/` — new subpackage
- `src/inksink/__main__.py` — conditionally start the Display Server thread
- `ansible/roles/display_server/` — new role
- `src/inksink/core/config.py` — new defaults for `apps.display_server`
- `Compositor.set_content()` gains an optional `mode` parameter (default
  `"1bit"`); existing callers are unaffected
